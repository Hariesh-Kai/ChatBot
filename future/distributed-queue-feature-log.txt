Update Date: 2026-02-16
Decision: Deferred for now (resume later)

Reason for deferral:
- Celery + RabbitMQ integration is implemented, but local Windows runtime setup is unstable.
- Work is paused as requested; keep this as a pending operations log.

Observed Issues During Setup:
- RabbitMQ service control without admin rights failed (`net start RabbitMQ` -> access denied).
- Commands failed when using placeholder/wildcard paths in CMD (for example `<version>` and `*` in `cd` path).
- `ERLANG_HOME` not set in new terminals caused:
  - `ERLANG_HOME not set correctly` in `rabbitmqctl.bat` and `rabbitmq-plugins.bat`.
- Service-mode cookie mismatch caused CLI auth failure:
  - Erlang distribution failed / cookie mismatch between service account and user CLI.
- RabbitMQ user-mode startup worked, management plugin enabled, and status command succeeded.
- Celery worker on Windows crashed repeatedly with `billiard` pool errors:
  - `PermissionError: [WinError 5] Access is denied`
  - repeated `SpawnPoolWorker-* exited with exitcode 1`
- Intermittent broker connectivity warning also observed after worker churn:
  - `Cannot connect to amqp://guest:**@127.0.0.1:5672//: timed out`

Current Mitigation Applied In Code:
- Windows-safe Celery defaults configured:
  - worker pool -> `solo`
  - concurrency -> `1`
- Startup script updated to launch worker with:
  - `--pool=solo --concurrency=1`
